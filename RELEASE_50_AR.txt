الإصدار 50.0.0 — استكمال الإدارة المتكاملة
============================================

الإضافات البرمجية في هذه الحزمة
-------------------------------
1) سجل أسرة موحد: ملف أسرة بمعرف داخلي ثابت وربطه بمعرف الحالة الرئيسي عند التطابق. لا يتم دمج أو حذف السجلات المتشابهة تلقائيًا، مع شاشة لمراجعة الحالات غير المرتبطة.
2) دورة المساعدات: طلب جديد، مراجعة، اعتماد، تجهيز، توزيع، إثبات استلام، أو رفض. يسجل تاريخ كل انتقال. عند اعتماد مرحلة التوزيع، ينشأ صرف مخزني مرتبط بالطلب إذا كان الرصيد كافيًا؛ ويطلب عند الاستلام اسم المستلم ووصف إثبات الاستلام.
3) المخازن المتقدمة: سجل حركات وارد/صرف/تحويل بين مخازن/تسويات، فحص الرصيد قبل الصرف، جرد ومقارنة الفعلي بالدفتر، وحساب قيمة تقديرية بمتوسط تكلفة الوارد. الجرد لا ينشئ تسوية تلقائية.
4) المحاسبة: قيود يومية متوازنة (مدين/دائن) مع منع حفظ القيد غير المتوازن، ومركز تكلفة مرتبط بالمشروع، وكشف أرصدة حسابات أولي.
5) التقارير: لوحة مؤشرات مختصرة، تصدير CSV، طباعة، وتصدير بيانات وحدات الإصدار 50 بصيغة JSON.
6) اختبارات التشغيل والنسخ: فحوصات محلية لحالة الواجهة وآلية الحفظ والوحدات، وتنزيل نسخة JSON كاملة، مع خيار دمج EXTRA من ملف JSON بعد تأكيد المستخدم.

الدمج والتوافق
---------------
- أضيفت الوحدة إلى الويب وWindows وAndroid/www وAndroid/assets/www.
- تم تحديث version.txt إلى 50.0.0.
- البيانات الجديدة تحفظ داخل EXTRA باستخدام آلية save الحالية؛ لا يوجد تعديل تلقائي على مخطط Supabase.

قيود مهمة — ما لم يكتمل أو لم يختبر
-----------------------------------
- سجل الأسرة الموحد يربط عبر رقم ملف الحالة أو معرفها؛ لا يوجد ترحيل/دمج تلقائي شامل لكل الحقول القديمة أو إزالة التكرارات.
- دورة المساعدات تعمل محليًا على مراحل متتابعة، لكنها لا تفرض بعد اعتمادًا مزدوجًا موثقًا حسب صلاحيات قاعدة البيانات أو توقيعًا إلكترونيًا؛ إثبات الاستلام وصف/مرجع وليس توقيعًا إلكترونيًا.
- المخازن لا تزال وحدة تشغيلية أولية: لا يوجد فصل محكم للأرصدة حسب المخزن في كل التقارير، ولا نظام دفعات/تشغيلات كامل أو تكلفة محاسبية معتمدة. التحويل يسجل طرفي الحركة على مستوى الصنف.
- القيود المزدوجة تسجل طرفًا مدينًا وطرفًا دائنًا لكل قيد، لكنها لا تتضمن بعد دليل حسابات معتمدًا، أرصدة افتتاحية، إقفال فترات، تسويات بنكية، أو قوائم مالية قانونية معتمدة.
- التقارير إدارية مختصرة وليست قوائم مالية رسمية.
- فحوصات QA داخل التطبيق محلية؛ لا تثبت المزامنة الحية أو RLS أو صلاحيات Supabase.
- لم يتم الاتصال بقاعدة Supabase الحية أو تنفيذ SQL، ولم يتم اختبار تعدد المستخدمين أو استعادة قاعدة البيانات.
- لم يتم بناء APK أو EXE أو تشغيل اختبارات على أجهزة فعلية.
- لا تستخدم بيانات مستفيدين حقيقية قبل مراجعة الصلاحيات وخصوصية التخزين والنسخ الاحتياطي على بيئة تجريبية.
